TruthLag: how fast do live Wikipedia revert counts catch up with the truth?

An edit that will be reverted looks fine at first. This page shows how long a live count has to wait before it agrees with the reconciled history, measured on a Bronze, Silver and Gold Delta lake built from the captured event streams and two History snapshots.

Every number is filled from docs/final/results.json at commit ddde933 (generated 2026-11-17T08:59:46Z). Technique sections marked "fallback" are replaced when a teammate's notebook arrives.

Hypotheses

H1: the lag has a long tail (fewer than 60% of eventual reverts known after 1 hour, and fewer than 95% after 48 hours)

Intervals come from a bootstrap over pages (2,000 resamples). The dashed line is the threshold set before the data was seen. "Not falsified" means both shares stay below their line; a share above its line falsifies H1.

Run it yourself

From the repository root, with TRUTHLAG_HW2_DIR=$PWD/ec-hw2 set.

  • .venv-lake/bin/python -m etl.time_travel then against now, on the real tables
  • .venv-lake/bin/python -m etl.stream_sss the Bronze-to-Silver step as a streaming query
  • .venv-lake/bin/python scripts/check_numbers.py every reported number against the lake
  • bash etl/build_all.sh the whole lake from the raw files
