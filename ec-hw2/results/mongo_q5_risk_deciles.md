# Mongo Q5: live revert-risk deciles

Mongo Q5 (spec 3.5), risk deciles: the LIVE cohort only (Atlas holds the history cohort only, so run it on the local database). It starts from revisions with the same stages as q5_truth_lag_preview ($lookup of revert_links for T and K, and of page_hour). Edits with a Wikimedia revert-risk score at save time are split into 10 groups of about equal size with $bucketAuto on live.revert_risk (_id.min and _id.max are the score range; the last group includes its max). A $unionWith adds one more group, 'no score': the revisions without a score. These are page creations (they never get a score; n_page_creations) and edits whose score event was not captured (n - n_page_creations). Per group: n, n_reverted_4d (T <= 345600 s, self-reverts count), the exact median T of those reverts ($push + $sortArray; $median in MongoDB 8.0 is only approximate), and for each wait w in ['now', '1 h', '1 d'] (index 0, 1, 2): at_risk_i = edits with T > w (never reverted counts as T = infinity) and event_i = those reverted within 4 days. queries/run_mongo.py then computes p = event_i / at_risk_i, the residual P(w < T <= 4 d | T > w), with a Wilson 95% interval in Python (run_mongo.wilson), and drops groups with n < 100.
