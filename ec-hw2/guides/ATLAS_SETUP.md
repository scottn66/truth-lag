# Atlas setup: one shared project, a free cluster, the load, and the screenshots

**Who:** the Data+MongoDB owner does parts A to C and F. Scott's Mac does part E (it has the data). Every member does part D on their own laptop.
**Time:** about 30 minutes for parts A to D, 5 to 15 minutes for the load (part E), and about 30 minutes for the screenshots (part F).
**Spec item:** section 3, "Scale-out: Atlas free tier (M0)", and the Atlas screenshots of the team plan.

What you get at the end:
- one Atlas project for Group 9, with all 4 members as Project Owner
- one free cluster (M0) with the database `truthlag`: the history cohort (`history_revisions` in report/FACTS.md, without `comment`), its `revert_links` (`history_revert_links`) and the 4 chart collections
- one read-only database user for each person, and one write user for loading
- 7 Atlas screenshots and 1 screenshot of Mongo Q5 from the local MongoDB, in `ec-hw2/results/figures/`

Names such as `history_revisions` or `mongo_q2_top_page_title` in this guide are keys of `report/FACTS.md`. Look up the value there: the values can change after a re-run, the keys do not.

Atlas changes its menus from time to time. If a button has a slightly different name, look for the closest one.

On Atlas, every human editor is a pseudonym (`editor_` + 10 hex digits, for example `editor_7f3a2b1c9d`), and `user.id` is empty. Bots keep their names. Still use the filter of step 20, so the screenshot shows one bot document only.

## Part A: the project and the cluster (Data+MongoDB owner, about 15 minutes)

**Skip this part if the project already exists.** Scott created the project and the cluster on 2026-10-24. Ask Scott to invite you as **Project Owner**, then accept the email invite (see step 3). Then go on with part B.

1. **Sign in.** Open https://cloud.mongodb.com and sign in (or create a free account).
   You should see your organization's home page with a "Projects" list.
2. **Create the project.** Click "New Project". Name it `truthlag-ec-hw2-group9` and click "Next".
3. **Invite all 4 members as Project Owner.** On the "Add Members" page, type each member's email address. For each one, set the role to **Project Owner**. Click "Create Project".
   - If you skipped this page: open the project, click the gear icon "Project Settings" (or "Access Manager"), then "Invite to Project", and add the same people with the role Project Owner.
   - Each member gets an email and must click "Accept". Someone without an Atlas account creates one first (free).
   - Why Project Owner: only a Project Owner can add a data source in Atlas Charts (see `ATLAS_CHARTS.md`).
4. **Create the free cluster.** In the project, click "Create" (or "Build a Database" / "+ Create cluster").
   - Choose **M0** (it says "Free").
   - Provider: **AWS**. Region: **Oregon (us-west-2)**, if it is offered. Otherwise take the closest US West region.
   - Name: `truthlag`. You cannot change the name later.
   - Remove the tick from "Preload sample dataset" (we do not need it).
   - MongoDB version: Atlas picks the version for M0. It should show **8.0** (the same as our Docker MongoDB). If it shows 7.0, our queries still work.
   - Click "Create Deployment".
   You should see the cluster card with "M0", "FREE", "AWS / Oregon (us-west-2)". It takes 1 to 3 minutes until it is ready.
5. If a "Connect to truthlag" window opens now, close it. We create the users and the IP list in parts B and C.

## Part B: database users (Data+MongoDB owner, about 5 minutes)

A database user is the user name and password inside the connection string. It is not the same as your Atlas login. If the users already exist, ask the person who made them for your own read-only user (in a private message), and go on with part C.

6. **Open the user list.** In the left menu, under "Security", click "Database Access" (newer menus: "Database & Network Access" > "Database Users"). Click "+ Add New Database User".
7. **The write user (for loading).**
   - Authentication method: Password. User name: `loader_scott`.
   - Click "Autogenerate Secure Password", then "Copy". Keep it in your password manager.
   - Database User Privileges: "Built-in Role" > **Read and write to any database**.
   - Click "Add User".
   - Only Scott's Mac uses this user.
8. **One read-only user per person.** Repeat step 7 four times, with the user names `ro_scott`, `ro_<first name of member 2>`, `ro_<member 3>` and `ro_<member 4>`, and the role **Only read any database**.
   - Use the autogenerated passwords. They have only letters and digits, so they work in a connection string without changes.
   - Send each person their own user name and password in a **private** message. Never put a password in the group chat, in GitHub or in a screenshot.
   You should see 5 users in the list: 1 with "readWriteAnyDatabase" and 4 with "readAnyDatabase".

## Part C: Network Access (Data+MongoDB owner, about 5 minutes)

Atlas only accepts connections from the IP addresses in its list.

9. In the left menu, under "Security", click "Network Access" (newer menus: "Database & Network Access" > "IP Access List"). Click "+ Add IP Address".
10. Choose **one** of these two ways:
    - **Each person's IP (safer).** Each person opens https://www.whatismyip.com and sends you their IPv4 address. Add each one, with a comment such as `ro_scott home`. Or each person, as Project Owner, clicks "Add Current IP Address" on their own laptop. Click "Confirm".
    - **A temporary entry for everyone (a class-project shortcut).** Click "Allow Access from Anywhere" (it fills in `0.0.0.0/0`). Turn on "This entry is temporary and will be deleted in" and choose **1 week**. Comment: `EC HW2 class project, temporary`. Click "Confirm".
      - Check the end date in the list. It must be **after 2026-10-30**. An entry made on 2026-10-24 ends on 2026-10-31. If yours ends earlier, add it again on 2026-10-25 or later.
      - This is a shortcut for a class project only. With `0.0.0.0/0`, anyone on the internet can try to connect, and only the passwords protect the cluster. Our data is public Wikipedia data, and the read-only users cannot change it. Do not do this with private data.
    You should see the entry with the status "Active" after about 1 minute.

## Part D: the connection string in `ec-hw2/.env` (every member, about 5 minutes)

11. **Copy the connection string.** Open the cluster page and click "Connect" > "Drivers". Choose the driver "Python" and the newest version. Copy the string. It looks like this:
    `mongodb+srv://<db_username>:<db_password>@truthlag.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=truthlag`
12. **Put it into `ec-hw2/.env`.** Open `ec-hw2/.env` in a text editor (make it first with `cp ec-hw2/.env.example ec-hw2/.env`, on Windows `copy ec-hw2\.env.example ec-hw2\.env`). Fill in these two lines, with **your own** read-only user and password, and without the `< >`:
    ```
    ATLAS_URI=mongodb+srv://ro_yourname:YourPassword@truthlag.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=truthlag
    ATLAS_DB=truthlag
    ```
    Save the file.
13. **Make sure it is never committed.** Run `git status --short ec-hw2/.env`. You should see **nothing**: the file is in `.gitignore`. If you use only the GitHub web page, never upload `.env`.
14. **Test the connection.**
    - Mac: `.venv/bin/python ec-hw2/check_setup.py`
    - Windows: `.venv\Scripts\python ec-hw2\check_setup.py`
    You should see a line for "MongoDB Atlas" that says `MongoDB 8.0...; database truthlag has 6 collections; revisions = about ... documents` (after part E; the number is `history_revisions`). If it fails, check your IP in Network Access, the user name and password, and your internet.

## Part E: load the data (Scott's Mac, 5 to 15 minutes)

The loader copies the history cohort **without** `comment`, the history `revert_links` and the 4 chart collections from the local data. It refuses to load if the estimate is over 400 MB (the free tier limit is 512 MB).

15. On Scott's Mac, `ATLAS_URI` uses the write user `loader_scott`. It is in `ec-hw2/.env.atlas` (read first by `config.py`) or in `ec-hw2/.env`. Both files are git-ignored. The chart collections must exist in the local MongoDB (`.venv/bin/python ec-hw2/queries/run_mongo.py` makes them).
16. **Estimate the size** (about 1 minute, no connection to Atlas):
    ```
    .venv/bin/python ec-hw2/load_mongo.py --target atlas --estimate-only
    ```
    You should see one line per collection (documents, bytes per document, MB), then the last line:
    ```
    estimated total ... MB; budget 400 MB (the free tier limit is 512 MB) -> fits
    ```
    The total is `atlas_estimate_mb`.
17. **Load.** It replaces what is on Atlas, so it needs `--confirm-overwrite`:
    ```
    .venv/bin/python ec-hw2/load_mongo.py --target atlas --confirm-overwrite
    ```
    You should see:
    - `connected to Atlas, database truthlag`
    - `revisions: ... documents` (`history_revisions`) and `revert_links: ... documents` (`history_revert_links`)
    - the index names
    - one line per chart collection with its document count (`chart_q1_hour_kind`, `chart_q3_time_to_revert`, `chart_q5_known_by`, `chart_q5_risk_deciles`)
    - a line with the Atlas `dbStats`.
    The time depends on the upload speed of the internet connection.
18. **Check in Data Explorer.** On the cluster card, click "Browse Collections" (newer menus: "Data Explorer" in the left menu). Open the database `truthlag`.
    You should see 6 collections: `revisions` (`history_revisions` documents), `revert_links` (`history_revert_links`), and the 4 chart collections with the counts that step 17 printed.
    - Scott runs step 17 again after every re-run of the pipeline. The 2026-10-24 fixes changed the pseudonyms, so Atlas is loaded again after that re-run.
    - After the live cutoff (after Mon 2026-10-26 5:05 PM PT, which is 2026-10-27 00:05 UTC), Scott runs step 17 again, so the chart collections get the final live numbers.

## If something goes wrong

| problem | what to do |
|---|---|
| `check_setup.py` says "cannot connect in 5 s" | Your IP is not in Network Access, or the temporary entry ended. Add it again (step 10). |
| "bad auth : authentication failed" | The user name or password in `ATLAS_URI` is wrong. Copy them again; remove the `< >`. |
| `STOP: ATLAS_URI is empty` | Fill in `ec-hw2/.env` (step 12). |
| `STOP: the estimate (...) is over config.ATLAS_BUDGET_MB` | Nothing was loaded. Tell Scott; the fallback is a smaller sample. |
| "user is not allowed to do action [insert]" during the load | `ATLAS_URI` uses a read-only user. Use `loader_scott` for the load. |
| Data Explorer shows no `truthlag` database | Part E has not run yet, or it stopped early. Look at its last lines. |
| the pseudonyms have 8 hex digits (`editor_` + 8) | Atlas still has a load from before the 2026-10-24 fixes. Ask Scott to run step 17 again. |
